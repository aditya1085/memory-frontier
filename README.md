# Memory Frontier — KV Cache vs. Brain-Inspired Synaptic Memory
🔗 **Live site:** https://web-production-c0829.up.railway.app
**DataForge 2026 — Pathway Track submission.**
Topic: *Associative Memory and Fast Weights* (with elements of *Synaptic Plasticity as Short-Term Memory* and *Key–Value Caching, Limitations, and Alternate Approaches*).

## The one-sentence claim

> A fixed-size Hebbian synaptic memory can match KV-cache retrieval accuracy at small context sizes, but accuracy degrades through interference as more facts are written — while a KV cache stays near-perfectly accurate but its memory grows without bound.

The whole artifact exists to let a learner test this sentence themselves, not just read it.

## Intended learner & prerequisites

Audience: an undergraduate CS/ML student or early-career ML engineer who knows what attention and a KV cache are, but has not necessarily encountered fast-weight / Hebbian memory models. No specific prior beyond that is required; the interactive controls are designed to make the mechanism visible without derivation.

## Learning objectives

After using this artifact, a learner should be able to:
1. Explain why a standard Transformer's KV cache grows linearly with context length.
2. Explain, with the actual update equation, how a fixed-size synaptic (Hebbian) memory avoids that growth.
3. Predict, and then verify, that this comes at a cost: interference between facts stored in the same fixed-size matrix.
4. State where this mechanism appears in Pathway's Dragon Hatchling (BDH) architecture, and where this prototype's simplification diverges from BDH's actual design.
5. Identify at least one limitation of the comparison (see "Limitations" below).

## Mathematical formulation

**KV Cache baseline.** Every written fact appends a `(key, value)` pair. Retrieval is brute-force cosine similarity search over all stored keys — the same computation full attention performs:

```
retrieved = values[argmax_i cos(query, keys[i])]
```

Memory: `O(N)` in the number of facts written (measured directly from array sizes, not estimated).

**Synaptic memory (Hebbian fast-weight prototype).** One fixed-size matrix `W` of shape `(dim, dim)`:

```
W_t = λ · W_(t-1) + η · (v kᵀ)
retrieved = W @ query
```

- `λ` (decay/retention factor, 0 < λ ≤ 1)
- `η` (learning rate)
- `k`, `v` — key and value vectors

Memory: `O(1)` with respect to sequence length — `W` never changes shape. This is the load-bearing claim, and it is checked by a unit test (`backend/tests/test_memory.py::test_synaptic_memory_is_fixed_size`) that writes 500 facts and asserts the byte size is unchanged.

**Retention curve** (Forgetting Lab). For a single write with no further updates, decay alone gives the exact closed form `strength_t = λ^t`, plotted directly — no simulation needed for that specific curve.

## Interactive substrate ("what can the learner actually change")

- **Playground**: memory dimension, decay λ, learning rate η, number of tracked facts → live re-run of the full benchmark sweep (50 to 10,000 facts), live charts.
- **Recall Lab**: type your own facts and a query, inject 0–10,000 distractors, see what each system actually retrieves, with similarity scores.
- **Forgetting Lab**: drag λ and watch both the theoretical retention curve and the empirical accuracy-vs-length curve update together.
- **Judge Demo**: one click, runs a fresh benchmark sweep server-side, prints the claim next to the numbers that just tested it.

## Connecting to Dragon Hatchling (BDH) — the required BDH module

This prototype is explicitly **not** a reimplementation of BDH. It isolates one mechanism — a Hebbian outer-product write into a memory — that is also present, in a much more elaborated form, inside BDH's design. The site's "BDH Module" section lays out the comparison in full; in short:

- BDH reformulates attention itself as **synaptic memory that updates as the model reads**, via Hebbian-style local updates between neuron-like units — not a single dense matrix update, but a scale-free graph of many local units.
- BDH's activations are **sparse and non-negative** (reported around 5% of neurons active at a time), which the paper connects to reduced interference and to monosemantic synapses (a synapse responding to one recognizable concept). This prototype's dense, unconstrained `W` has none of that structure — which is very likely *why* this prototype's accuracy degrades faster with scale than BDH's own reported long-context behavior.
- **BDH-CQ**, a later system in the same family, uses the same family of ideas to let a model adapt from demonstrations at inference time — writing them into recurrent memory — and reason iteratively in a continuous latent workspace, without a verbalized chain-of-thought and without updating any weights at inference. Its evaluation-task adaptation lives entirely in that recurrent state, which is the same *place* (state, not weights) where this prototype's `W` also lives — but BDH-CQ's iterative latent reasoning loop is not something this prototype implements or claims to.

Any toy model or independent reimplementation in this project must be, and is, identified as such rather than presented as an official BDH model, per the track's rules.

## Installation & running locally

### Backend
```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```
This also serves the frontend at `http://localhost:8000/` (the `StaticFiles` mount in `main.py` serves `../frontend`).

### Frontend only (optional, if you want to point it at a different backend)
No build step. Just open `frontend/index.html` directly, or serve the folder with any static file server, and set:
```html
<script>window.MEMORY_FRONTIER_API = "https://your-backend-url";</script>
```
in `index.html` before `assets/app.js` loads.

### Tests
```bash
cd backend
pip install pytest
pytest tests/ -v
```
(7 tests: linear KV growth, fixed synaptic size, perfect small-set KV recall, degradation with scale, retention curve monotonicity, and the λ=1 no-decay edge case.)

### Regenerating the precomputed benchmark
```bash
python experiments/benchmark.py
```
Overwrites `experiments/results/benchmark_results.json` (and the copy bundled at `frontend/assets/benchmark_results.json` should be re-copied after). Every number in it comes from `backend/memory/evaluator.py` — nothing is hand-typed.

## Benchmark methodology

For each sequence length `N`, `num_target_facts` "important" facts and `N - num_target_facts` distractor facts are generated as random unit vectors, written into **both** memories in the same shuffled order, then the target facts are queried. Accuracy is the fraction correctly retrieved (nearest-neighbor decode against the known value vocabulary). Memory is measured directly from array byte sizes, not estimated. Latency is measured with `time.perf_counter()` around the retrieval call. All runs use a fixed seed (42) for reproducibility; re-running `experiments/benchmark.py` reproduces the same numbers bit-for-bit.

**Interference/forgetting signal**: target facts are split into those written in the first vs. second half of the sequence; the gap between synaptic accuracy on early- vs. late-written facts is reported as `interference_gap`.

## Limitations (disclosed, not hidden)

- The synaptic memory here is a **deliberately simplified** dense Hebbian update. It has none of BDH's sparsity, non-negativity, or scale-free connectivity — features BDH's own paper connects to reduced interference. This prototype's degradation curve is therefore an **upper bound on the problem**, not a measurement of BDH itself.
- The Recall Lab's free-text embedding (`text_to_vector` in `backend/memory/evaluator.py`) is a **deterministic hash-based toy embedding** with no semantic understanding. It distinguishes distinct strings; it does not understand language, synonyms, or meaning.
- All accuracy numbers are measured on a **controlled, uncorrelated associative-recall benchmark** (random unit vectors as keys/values). Real text has redundancy and structure a language model can exploit that this synthetic benchmark does not capture — these numbers should not be read as a prediction of real-world long-context model behavior.
- "O(1) space" refers specifically to the memory matrix's size with respect to sequence length, for a fixed memory dimension — not to compute cost (writing and reading `W` still costs `O(dim²)` per step) and not to every resource the system uses.
- We did not run or reproduce BDH or BDH-CQ itself; the BDH module is built from the architecture's published equations, diagrams, and reported results (see Primary sources), as the track's rules explicitly permit.
